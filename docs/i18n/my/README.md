## 💰 တစ်လလျှင် Third-Party အခမဲ့ Tier များမှ Token ~1.62B

</div>

> **သင့်ကိုယ်ပိုင် provider အကောင့်များကို အသုံးပြုပါ။** ဤပမာဏသည် သီးခြားအသုံးပြုခွင့်ရှိသော third-party အခမဲ့ tier များကို စုစည်းခန့်မှန်းထားခြင်းဖြစ်ပြီး OmniRoute မှ token ထောက်ပံ့ပေးခြင်း မဟုတ်ပါ။ လိုအပ်ပါက စာရင်းသွင်းပြီး credential များရယူကာ သင်အသုံးပြုနိုင်သည့် provider များကို ချိတ်ဆက်ပါ။ Provider တစ်ခုချင်းစီသည် ၎င်း၏ limit၊ ရရှိနိုင်မှုနှင့် သတ်မှတ်ချက်များကို ကိုယ်တိုင်ထိန်းချုပ်ပါသည်။
>
> အခမဲ့ tier များကို ကိုယ်တိုင်ပေါင်းစည်းအသုံးပြုရခြင်းမှာ ခက်ခဲပါသည် — SDK များ ဒါဇင်နှင့်ချီ၊ rate limit များ ဒါဇင်နှင့်ချီရှိပြီး သင့်တွင် အမှန်တကယ် မည်မျှရှိသည်ကိုလည်း မသိနိုင်ပါ။ OmniRoute သည် **recurring pool key 34 ခုအတွင်း အခမဲ့ tier entry 465 ခုကို စုစည်းမှတ်တမ်းတင်ထားပြီး** ထုတ်ပြန်ထားသော အပြုသဘောဆောင်သည့် လစဉ် budget ရှိသော **pool 17 ခုနှင့် model တစ်ခုချင်းစီအလိုက် Groq cap ငါးခု** မှ token စုစုပေါင်းကို တွက်ချက်ပေးပါသည်။ Shared pool တစ်ခုချင်းစီကို တစ်ကြိမ်သာ ရေတွက်ထားပါသည်။ ဒေသဆိုင်ရာ identity စစ်ဆေးပြီးမှသာ ဖွင့်ပေးသည့် quota များ (ယနေ့တွင် ModelScope) ကို သီးခြားဖော်ပြထားပြီး၊ ဒေသဆိုင်ရာ identity အတည်ပြုချက်နောက်တွင် +~6M ရှိသော်လည်း headline ထဲတွင် မပေါင်းထည့်ထားပါ။ ရလဒ်ကို dashboard (`/dashboard/free-tiers`) တွင် ဆက်လက်ကြည့်ရှုနိုင်ပါသည်။

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute အခမဲ့ tier budget ကတ် - တစ်လလျှင် ပုံမှန်အခမဲ့ token ~1.62B၊ signup credit များပါဝင်သည့် ပထမလတွင် ~2.22B အထိ၊ endpoint တစ်ခုအောက်တွင် catalog ပြုလုပ်ထားသော အခမဲ့ tier entry 465 ခုကို လွှမ်းခြုံထားသည့် မှတ်တမ်းတင်ထားသော recurring pool key 34 ခုမှ ရရှိသည်။ Pool တစ်ခုကို တစ်ကြိမ်သာ ရေတွက်ထားသည့် ရိုးသားသော pool-deduped တွက်ချက်မှုဖြစ်ပြီး၊ ထုတ်ပြန်ထားသော အပြုသဘောဆောင်သည့် လစဉ် token budget ရှိသော recurring pool 17 ခုနှင့် model တစ်ခုချင်းစီအလိုက် Groq cap ငါးခုလည်း ပါဝင်သည်။ Provider 12 ခုကို terms-risk catalog တွင် ရှောင်ရန်အဖြစ် သတ်မှတ်ထားသောကြောင့် သင်ကိုယ်တိုင် ဆုံးဖြတ်နိုင်သည်။ Budget bar တွင် Mistral 1B၊ Nara 210M၊ LLM7 150M၊ xKiro 150M၊ Groq 30M (model တစ်ခုချင်းစီအလိုက် cap ငါးခု) နှင့် ပိုမိုသေးငယ်သော pool များ၊ ထို့အပြင် ပထမလ signup credit များနှင့် အမြဲတမ်းအခမဲ့ဖြစ်ပြီး token cap မရှိသော provider များကို သီးခြားဖော်ပြထားသည်။ ထို့ကြောင့် headline ကို မတိုးစေပါ။ /dashboard/free-tiers တွင် လက်ရှိအသုံးပြုပြီး/ကျန်ရှိသည့် ပမာဏကို ပြသထားသည်။"/>

> Live `/dashboard/free-tiers` စာမျက်နှာ၏ လှုပ်ရှားသည့် အနှစ်ချုပ်။ နည်းလမ်းအပြည့်အစုံ (pool dedupe၊ credit tier များ၊ provider သတ်မှတ်ချက်များ) - **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**။
>
> <sub>ဤကိန်းဂဏန်းများကို live catalog နှင့် နှစ်ပတ်တစ်ကြိမ် ပြန်လည်စစ်ဆေးထားပြီး **နှစ်ဖက်စလုံးသို့ ပြောင်းလဲနိုင်သည်** — provider တစ်ခုက အခမဲ့ tier ကို ရပ်ဆိုင်းပါက ကိန်းဂဏန်း လျော့ကျမည်၊ အသစ်တစ်ခု ရောက်ရှိလာပါက တိုးလာမည်။ အနီးစပ်ဆုံး အမြင့်ဆုံးဖြစ်နိုင်သည့် အခြေအနေကို အပေါ်သို့ဝိုင်းမထားဘဲ catalog က အမှန်တကယ် တွက်ချက်ထားသည့် ပမာဏကိုသာ ထုတ်ပြန်ပါသည်။</sub>

## 🆓 ထည့်သွင်းပြီး provider ကို ချိတ်ဆက်ကာ endpoint တစ်ခုမှတစ်ဆင့် လမ်းကြောင်းပို့ပါ

</div>

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="အဆင့် ၃ ဆင့် — OmniRoute ကို ထည့်သွင်းပြီး စတင်ပါ၊ သင့်ကိုယ်ပိုင်အကောင့် သို့မဟုတ် API key ဖြင့် သတ်မှတ်ချက်နှင့်ကိုက်ညီသော provider တစ်ခုကို ချိတ်ဆက်ပါ၊ ထို့နောက် OmniRoute API key နှင့် model auto ကို အသုံးပြုကာ သင့် tool ကို localhost:20128/v1 သို့ ညွှန်ပြပါ။ လမ်းကြောင်းပို့ခြင်းသည် ရရှိနိုင်သော သတ်မှတ်ချက်နှင့်ကိုက်ညီသည့် ချိတ်ဆက်မှုများနှင့် provider ကန့်သတ်ချက်များအပေါ် မူတည်သည်။"/>

```bash
# Provider တစ်ခုကို ချိတ်ဆက်ပြီးနောက် သင်၏ OmniRoute key ကို Dashboard → Endpoints မှ ကူးယူပါ:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>`auto` သည် သတ်မှတ်ချက်နှင့်ကိုက်ညီသော route တစ်ခု လိုအပ်သည်။ အသစ်ထည့်သွင်းထားသော installation တစ်ခုတွင် သတ်မှတ်ချက်နှင့်ကိုက်ညီသော keyless target များ မရှိနိုင်သကဲ့သို့ keyless provider တစ်ခုသည် third-party client များကို ငြင်းပယ်နိုင်သည်။ `tos: avoid` ဟု သတ်မှတ်ထားသော provider များ၊ Kiro အပါအဝင်၊ ကို ပုံမှန်အားဖြင့် အလိုအလျောက်လမ်းကြောင်းပို့ခြင်းမှ ဖယ်ထုတ်ထားသည်။ အကောင့်တစ်ခုကို ချိတ်ဆက်ခြင်းသည် ထို setting ကို အစားမထိုးနိုင်ပါ။ Provider တစ်ခုကို မရွေးချယ်မီ [အခမဲ့အဆင့်များ လမ်းညွှန်](docs/getting-started/FREE-TIERS-GUIDE.md) ကို ကြည့်ပါ။</sub>

<sub>📦 **Python, Node.js, PHP, နှင့် cURL** အတွက် ကူးယူပြီး ချက်ချင်းအသုံးပြုနိုင်သော quickstart script များ → [`examples/quickstart/`](examples/quickstart/)</sub>

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute ခံနိုင်ရည် — လွတ်လပ်သော ကိုယ်တိုင်ပြန်လည်ပြုပြင်နိုင်သည့် အလွှာ 3 ခု၊ ချို့ယွင်းမှုတစ်မျိုးချင်းစီအတွက် သင့်တော်သောအလွှာ။ အလွှာ 1 ဝန်ဆောင်မှုပေးသူ circuit breaker (ဝန်ဆောင်မှုပေးသူတစ်ခုလုံး): 408/5xx များတွင်သာ အလုပ်လုပ်ပြီး၊ OAuth အတွက် 8× / API-key အတွက် 12× / local အတွက် 2× အဆင့်သတ်မှတ်ချက်များ၊ HALF-OPEN စမ်းသပ်မှုအဖြစ် 60s/30s/15s အကြာတွင် ပြန်လည်သတ်မှတ်ခြင်း၊ နှောင့်နှေးပြန်လည်ကောင်းမွန်ခြင်း၊ OPEN ဖြစ်နေစဉ် combo သည် နောက်ဝန်ဆောင်မှုပေးသူထံ ပြန်လည်လမ်းကြောင်းပြောင်းသည်။ အလွှာ 2 ချိတ်ဆက်မှု cooldown (key/account တစ်ခု): OAuth အတွက် အခြေခံ 5s / API-key အတွက် 3s၊ anti-thundering-herd ကာကွယ်မှုပါဝင်သော exponential ×2 backoff၊ 429 သည် Retry-After ကို လိုက်နာပြီး အောင်မြင်ပါက error state အားလုံးကို ရှင်းလင်းသည်၊ cooling ပြုလုပ်နေသော key တစ်ခုကို ကျော်သွားသော်လည်း sibling key များက ဆက်လက်ဝန်ဆောင်မှုပေးသည်။ အလွှာ 3 မော်ဒယ် lockout (မော်ဒယ်တစ်ခု): မော်ဒယ်တစ်ခုချင်းစီ၏ 429၊ local 404 သို့မဟုတ် mode denial များသည် ထိုမော်ဒယ်တစ်ခုတည်းကိုသာ lock လုပ်ပြီး ချိတ်ဆက်မှုတစ်ခုလုံးကို မည်သည့်အခါမျှ lock မလုပ်ပါ။ Terminal state များ (banned, expired, credits exhausted) သည် operator အတွက်ဖြစ်ပြီး cooldown များအတွက် မဟုတ်ပါ။"/>

## 📡 OmniRoute Radar

အထက်တွင် မှတ်တမ်းပြုစုဖော်ပြထားပြီး pool အလိုက် ထပ်နေမှုများကို ဖယ်ရှားထားသည့် catalog မှ အဓိက free-tier ပမာဏသည် **တစ်လလျှင် token ~1.62B** အဖြစ် ဆက်လက်ရှိနေပါသည်။
ယာယီ provider signup credit များကြောင့် ပထမလတွင် သီးခြားစီ **~2.22B** အထိ တိုးမြင့်နိုင်ပါသည်။ Radar သည် OmniRoute release များကြားတွင် free-model ရရှိနိုင်မှုဆိုင်ရာ အချက်အလက်များကို ပိုမိုလတ်ဆတ်စွာ ရယူလိုသူများအတွက် စိတ်ကြိုက်ရွေးချယ်အသုံးပြုနိုင်သည့်၊ လက်မှတ်ရေးထိုးအတည်ပြုထားသော catalog overlay တစ်ခုဖြစ်ပါသည်။ community catalog နှင့် လက်ရှိရှိပြီးသား အခမဲ့ feature အားလုံးသည် ဆက်လက်၍ အခမဲ့ဖြစ်ပါသည်။

ပံ့ပိုးသူများသည် live catalog နှင့် ထပ်ဆောင်း provider အခွင့်အလမ်းများကို ရရှိနိုင်ပါသည်။ Provider များ၏ ရရှိနိုင်မှုအပေါ် မူတည်၍ ၎င်း၏ သီးခြားပြောင်းလဲနိုင်သော အမြင့်ဆုံးပမာဏမှာ **အများဆုံး တစ်လလျှင် token ခန့်မှန်းခြေ 3B** ဖြစ်ပါသည်။
ထိုအမြင့်ဆုံးပမာဏသည် အာမခံချက်မဟုတ်ပါ။ Provider များသည် quota၊ eligibility၊ model သို့မဟုတ် region များကို အချိန်မရွေး ပြောင်းလဲနိုင်ပါသည်။

Radar သည် opt-in ဖြစ်ပြီး GET-only ဖြစ်ပါသည်။ OmniRoute client သည် prompt များ၊ traffic၊ provider configuration၊ usage telemetry သို့မဟုတ် local announcement-dismiss state တို့ကို upload မလုပ်ပါ။ Eligibility နှင့် လက်ရှိ catalog အကြောင်းကို **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)** တွင် လေ့လာနိုင်ပါသည်။

**OmniRoute မှတစ်ဆင့် ပံ့ပိုးထားသော CLI မည်သည့် tool ကိုမဆို တစ်ကြိမ်တည်းအမိန့်ဖြင့် မောင်းနှင်နိုင်သည်** — config ဖိုင်များ မရေးရန်လိုအပ်ပါ၊
credentials များကို process တစ်ခုချင်းစီအလိုက် ထည့်သွင်းပေးပြီး၊ Qwen/Gemini များအတွက် သီးသန့်သုံးစွဲခွင့်ရှိသော home ကိုဖန်တီးပေးသည်။

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # OpenAI Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# သို့မဟုတ် provider+model ကို ကိုယ်တိုင်ရွေးချယ်ပြီး tool ၏ ကိုယ်ပိုင် config ကိုရေးနိုင်သည်။
omniroute configure codex          # ထို့အပြင်: claude opencode qwen aider goose gemini cline continue kilo 5dive
```

မည်သည့်အမိန့်မဆို လက်ရှိ remote context (`omniroute connect <host>`) ကို လေးစားလိုက်နာသည်၊ `--dry-run`
ဖြင့် အတိအကျ env/args များကို အကောင်အထည်မဖော်မီ ကြိုတင်ကြည့်ရှုနိုင်ပြီး၊ `--api-key-env NAME` သည်
သင့် shell မှာ secrets များ ထားရှိခြင်းမှ ကာကွယ်ပေးသည်။ → [CLI ပေါင်းစည်းမှုများ](docs/guides/CLI-INTEGRATIONS.md)

## 🔌 အပြည့်အစုံ CLI + A2A & MCP

</div>

> Server အပြင် OmniRoute သည် **command-line cockpit အပြည့်အစုံ** ဖြစ်ပြီး **command 80+ ခု** ပါဝင်သည့်အပြင် AI agent တစ်ခုက **ကိုယ်တိုင်** ထိန်းချုပ်မောင်းနှင်နိုင်ရန် open agent protocol များလည်း ပါဝင်သည်။

### ⌨️ တကယ့် CLI တစ်ခု (`start` တစ်ခုတည်းမဟုတ်)

```bash
omniroute               # gateway + dashboard ကို serve လုပ်သည် (port 20128)
omniroute chat          # အပြန်အလှန် TUI chat client (slash: /model /combo /skill /memory)
omniroute setup         # ပထမဆုံးအကြိမ် run ရန် လမ်းညွှန် wizard
omniroute doctor        # providers၊ ports၊ native deps များကို စစ်ဆေးခြင်း
```

### 🛰️ Remote mode — CLI ကို ဒီနေရာတွင် run လုပ်ပြီး OmniRoute ကို VPS ပေါ်တွင် run လုပ်ခြင်း

Server ပေါ်တွင် OmniRoute ရှိပါသလား။ **တူညီသော CLI** ဖြင့် သင့် laptop မှ မောင်းနှင်နိုင်သည်။ Scoped access token ဖြင့် တစ်ကြိမ် login ဝင်လိုက်ပါ၊ ထို့နောက် command တိုင်းသည် remote ကို target လုပ်မည်။

```bash
omniroute connect 192.168.0.15            # password → scoped token၊ context တစ်ခုအဖြစ် သိမ်းဆည်းသည်
omniroute models                         # ← REMOTE server ပေါ်တွင် run လုပ်သည်
omniroute configure codex                 # ← remote model တစ်ခုကို ရွေးပြီး local Codex profile ကို ရေးသားသည်
omniroute tokens create --name ci --scope read   # အခြားစက်များအတွက် ပိုမိုကန့်သတ်ထားသော token များ ထုတ်ပေးသည်
omniroute contexts use default            # ← local server သို့ ပြန်ပြောင်းသည်
```

Token များကို `read` / `write` / `admin` အဖြစ် scope သတ်မှတ်နိုင်သည်။ Process-spawning routes များသည် loopback-only အဖြစ်သာ ဆက်လက်ရှိမည်။

- **🪄 အထွက်ပုံစံများ** _(အထွက်ဝင်ရိုးစတီယာရင်)_ — အဆုံးအဖြတ်ပေးသော၊ ကက်ရှ်-ဘေးကင်းသော တုံ့ပြန်မှုပုံသဏ္ဍာန် ညွှန်ကြားချက်များကို ထိုးသွင်းခြင်း၊ တစ်ခုချင်းစီကို `lite` / `full` / `ultra` ပြင်းထန်မှုတွင် ပေါင်းစပ်နိုင်သည်။ စတိုင်တစ်ခုထည့်ခြင်းသည် တစ်ကြောင်းတည်းစာရင်းသွင်းခြင်းဖြစ်သည်-
  - **Terse စကားပြေ** — drop filler / articles / hedging; နည်းပညာဆိုင်ရာ ပစ္စည်းများကို အတိအကျ ထိန်းသိမ်းပါ။
  - **ကုဒ်နည်းတယ်။** — "lazy senior dev" YAGNI: အသေးငယ်ဆုံးသော လုပ်ဆောင်မှုပြောင်းလဲမှု၊ တောင်းဆိုထားသည့် ငြမ်းမရှိပါ။
  - **Ponytail (ပျင်းရိသော အကြီးတန်း dev)** — YAGNI လှေကားကိုတက်ပါ၊ မူလအကြောင်းအရင်းကိုဖြေရှင်းပါ၊ အသေးဆုံးအလုပ်လုပ်ပုံကွဲပြားသည်။
  - **ငါ့မှာ ADHD (လုပ်ဆောင်ချက်-ပထမ)** — နောက်လုပ်ဆောင်ချက်က ဦးဆောင်သည်၊ နံပါတ်တပ်ထားသော ခြေလှမ်းများ၊ ခိုင်မာသော နောက်ထပ်ခြေလှမ်းတစ်ခု၊ အကြိုအပို့မရှိပါ။
  - **Terse CJK (文言)** — ဂန္ထဝင်-တရုတ် အစွန်းရောက်စတိုင် ( `zh` တွင် ကန့်သတ်ထားသည်။
- **🎯 Adaptive context-budget** _(the dial)_ — instead of one on/off token threshold, escalate the cheapest, most-lossless engines only as far as needed to **fit the model's context window**. Policy: `reserve-output` (default, model-aware) · `percentage` · `absolute`. Mode: `floor` (guarantee fit) · `replace-autotrigger` (your explicit choice wins) · `off` (legacy threshold).
- **🎛️ ဘယ်မှာ compression ဆုံးဖြတ်သည်** _(ရှေ့တန်း၊ မြင့်မားသော → နိမ့်)_ — per-request `x-omniroute-compression` ခေါင်းစီး › လမ်းကြောင်း-တွဲဖက်ကို ထပ်ရေးခြင်း › အသက်ဝင်နေသော ပရိုဖိုင် › adaptive / အလိုအလျောက် အစပျိုးခြင်း › panel default › ပိတ်သည်။ အသုံးပြုထားသော အစီအစဉ်သည် `X-OmniRoute-Compression: <mode>; source=<source>` တုံ့ပြန်မှု ခေါင်းစီးတွင် ပဲ့တင်ထပ်သည်။

တိုကင်အဆင့်သတ်မှတ်၍ အလိုအလျောက်အစပျိုးခြင်း၊ လိုက်လျောညီထွေရှိသော ဒိုင်ခွက်ပေါ်လှန်ပါ၊ အမည်ပေးထားသော ပရိုဖိုင်ကို ပင်ထိုးပါ၊ တောင်းဆိုမှုတစ်ခုအတွက် တစ်ကြိမ်သတ်မှတ်ပါ၊ သို့မဟုတ် အလုပ်တာဝန်နှင့်ကိုက်ညီသည့် လမ်းကြောင်းပြပေါင်းစပ် — အတွက် ပိုက်လိုင်းတစ်ခုသတ်မှတ်ပါ။ အော့ဖ်လိုင်းရွေးချယ်မှုတစ်ခု** eval ကြိုးကြိုး** (`npm run eval:compression`) ပြောင်းလဲမှုတစ်ခုကို သင်မမြှင့်တင်မီ ပင်ချိတ်ထားသော ကော်ပိုဆက်တစ်ခုပေါ်တွင် စုဆောင်းငွေကို သစ္စာစောင့်သိမှုနှင့် အမှတ်ပေးသည်။

**1) Install လုပ်ပြီး run လိုက်ပါ။**

```bash
npm install -g omniroute
omniroute
```

> 💡 `npm warn ERESOLVE` သို့မဟုတ် peer-dep သတိပေးချက်များကိုကြည့်ပါလား။ [သူတို့က အန္တရာယ်ကင်းတယ်](docs/guides/TROUBLESHOOTING.md#npm-install-warnings-eresolve--peer--deprecated) ။** npm 11 သို့မဟုတ် နောက်ပိုင်းတွင် အသုံးပြုနေပါသလား။** npm သည် ပက်ကေ့ခ်ျဘဝသံသရာ script များကို ခွင့်မပြုပါက ပိတ်ဆို့နိုင်သည်။ ၎င်း၏ မူရင်း runtime ဖိုင်များကို ပြင်ဆင်ရန် OmniRoute's `postinstall` (`node scripts/build/postinstall.mjs`) လိုအပ်သည်။ တစ်ကမ္ဘာလုံးတွင် ထည့်သွင်းသည့်အခါ npm ၏သတိပေးချက်တွင် အမည်ပေးထားသည့် ပက်ကေ့ဂျ်များကို ခွင့်ပြုပါ။ OmniRoute 3.8.55 ဖြင့် အစီရင်ခံထားသော ပက်ကေ့ဂျ်အတွက်-
>
> `bash npm install -g --allow-scripts=omniroute,keytar,onnxruntime-node,@parcel/watcher,@swc/core,protobufjs,esbuild omniroute `
>
> နောင်ကမ္ဘာလုံးဆိုင်ရာ ထည့်သွင်းမှုများအတွက် ဤခွင့်ပြုစာရင်းကို ပြန်လည်အသုံးပြုရန်၊ ၎င်းကို တစ်ကြိမ်တည်းသတ်မှတ်ပါ၊ ထို့နောက် ပုံမှန်အတိုင်း ထည့်သွင်းပါ-
>
> `bash npm config set allow-scripts=omniroute,keytar,onnxruntime-node,@parcel/watcher,@swc/core,protobufjs,esbuild --location=user npm install -g omniroute `
>
> မှီခိုမှုစာရင်းသည် ထုတ်ဝေမှုများကြားတွင် ပြောင်းလဲနိုင်သည်။ npm သည် အခြားစာရင်းတစ်ခုကို တိုင်ကြားပါက၊ ထိုသတိပေးချက်မှ ပက်ကေ့ခ်ျအမည်များကို အသုံးပြုပါ။ ပက်ကေ့ဂျ်တစ်ခုအား ခွင့်ပြုခြင်းသည် ၎င်း၏ထည့်သွင်းမှု scripts များကို လုပ်ဆောင်ရန် ခွင့်ပြုသည်။** Gemini Web သို့မဟုတ် အခြားဝဘ်-ကွတ်ကီးဝန်ဆောင်မှုကို အသုံးပြုနေပါသလား။** npm ပက်ကေ့ဂျ်တွင် Playwright ပါဝင်သော်လည်း ၎င်း၏ Chromium binary မဟုတ်ပါ။ ပထမဆုံး ဝဘ်-ပံ့ပိုးသူ တောင်းဆိုမှု မပြုလုပ်မီ [Playwright Chromium စနစ်ထည့်သွင်းမှု](docs/guides/TROUBLESHOOTING.md#gemini-web-and-playwright-chromium) မှတ်စုကို ကြည့်ပါ။

`http://localhost:20128` · API at `http://localhost:20128/v1` ရှိ ဒက်ရှ်ဘုတ်။

**2) သင့်ကိုယ်ပိုင်အကောင့်ကို အသုံးပြု၍ အရည်အချင်းပြည့်မီသောဝန်ဆောင်မှုပေးသူကို ချိတ်ဆက်ပါ။**

ဒက်ရှ်ဘုတ် →** ပံ့ပိုးပေးသည်။** → သင့်အသုံးပြုမှုကိစ္စတွင် → API ကိုက်ညီသည့် လက်ရှိသတ်မှတ်ချက်များနှင့် ခွဲတမ်းရှိသည့် ဝန်ဆောင်မှုပေးသူကို ရွေးချယ်ပါ သို့မဟုတ် ၎င်း၏အကောင့်စီးဆင်းမှုကို အပြီးသတ်ပါ။ အခမဲ့အဆင့်များသည် စာရင်းသွင်းခြင်း၊ အတည်ပြုချက် သို့မဟုတ် ငွေပေးချေမှုနည်းလမ်းတစ်ခု လိုအပ်နိုင်ပါသည်။ [အခမဲ့အဆင့်လမ်းညွှန်ကို](docs/getting-started/FREE-TIERS-GUIDE.md) ပြန်လည်သုံးသပ်ပါ။ သော့မဲ့ရရှိနိုင်မှုကို အာမမခံနိုင်ပါ၊ နှင့် `tos: avoid` အမှတ်အသားပြုထားသည့် ဝန်ဆောင်မှုပေးသူများကို `auto` မှ ဖယ်ထုတ်ထားသည်။

**3) သင်၏ coding tool ကိုညွှန်ပါ။**

```txt

```

curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"

သင့်ဖောက်သည်သည် စိတ်ကြိုက်ခေါင်းစီးများကို မပေးပို့နိုင်ပါက၊ OmniRoute တိုကင်ယူထားသော လိုက်ဖက်ညီသော aliases များကိုလည်း ဖော်ထုတ်သည်-

## 📦 နောက်ထပ် ထည့်သွင်းနည်းများ — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` follows the highest **published** stable SemVer. It does not track git `main`. Pin `:X.Y.Z` for GitOps. See [Docker Release Channels](docs/guides/DOCKER_GUIDE.md#release-channels).The image pins **`OMNIROUTE_MEMORY_MB=1024`**. That is enough for the dashboard and a light chat. **Coding agents** (`POST /v1/responses` from Claude Code, Codex, Grok, …) need a much larger V8 heap or the process `FATAL ERROR`s at ~12 GiB under two overlapping long contexts. Size the container above the heap (native buffers sit outside V8):

| အလုပ်ဝန်                             | အမှိုက်ပုံ (`-e OMNIROUTE_MEMORY_MB`) | ကွန်တိန်နာ (`--memory`) |
| ------------------------------------ | ------------------------------------- | ----------------------- |
| ဒက်ရှ်ဘုတ် / အလင်းစကားပြောခန်း       | `1024` (ပုံသေပုံသေ)                   | ≥ 2 ဂရမ်                |
| coding အေးဂျင့်တစ်ခု                 | `8192`                                | ≥ 10 ဂရမ်               |
| နှစ်ခုပြိုင်တူ `/v1/responses` အရှည် | `10240`–`12288`                       | ≥ 12-16 ဂရမ်            |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

ဇယားအပြည့်အစုံ- [Docker လမ်းညွှန် — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents) ။

> **Docker ချန်နယ်ကို အကြိုထုတ်လွှတ်ခြင်း-** `diegosouzapw/omniroute:next` နှင့် `diegosouzapw/omniroute:next-web` လက်ရှိ ပုံသေ `release/v*` ဌာနခွဲကို လိုက်နာသည်။ ဤပြောင်းလဲနိုင်သော တဂ်များကို မထုတ်ဝေရသေးသော ပြင်ဆင်မှုများကို စမ်းသပ်ရန်အတွက်သာ ရည်ရွယ်ပါသည်။** ထုတ်လုပ်မှုအတွက် မပံ့ပိုးပါ။** . Standard `bun install` နှင့် global installation (`bun install -g omniroute`) ကို Bun runtime detection မှတဆင့် ပံ့ပိုးပေးသည်-

- **Built-in `bun:sqlite`** : OmniRoute Bun အောက်တွင် လည်ပတ်နေချိန်တွင် Bun၏ built-in `bun:sqlite` ရိုက်ဘာကို အသုံးပြု၍ `better-sqlite3` တွင် Node.js သို့မဟုတ် `sql.js` သို့ ပြန်ကျသွားသည် .
- **dev တွင် အလိုအလျောက် Webpack အစုအဝေး ရွေးချယ်မှု** : Development (`bun run dev`) သည် Bun အလိုအလျောက် သိရှိပြီး ဇာတိ V8 ချိတ်ဆက်မှု မလိုက်ဖက်ခြင်းများကို ကာကွယ်ရန် Webpack ၏ မျက်နှာသာဖြင့် Turbopack ပိတ်သည်။ ထုတ်လုပ်မှုတည်ဆောက်မှုများ (`bun run build`) သည် Node ပေါ်ရှိ အတိအကျအတိုင်း `OMNIROUTE_USE_TURBOPACK` အတိအကျလိုက်နာပါသည်- Turbopack မူရင်းအတိုင်း၊ `OMNIROUTE_USE_TURBOPACK=0` ဖြင့် Webpack ဖြင့်တည်ဆောက်မည် (`Dockerfile.bun` သည် `--build-arg` အဖြစ်ဖော်ပြသည်။
- **သီးသန့် Bun Dockerfile** : ဇာတိ Bun ထုတ်လုပ်မှု ဖြ`docker build -f Dockerfile.bun -t omniroute:bun .`်ကျက်မှုအတွက် ဘက်စုံအဆင့် `Dockerfile.bun` ။

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ ပိုမိုမြန်ဆန် / ပျော့ပျောင်းသောထည့်သွင်းမှု (ဇာတိတည်ဆောက်မှုကိုကျော်သွား)**

မူလ SQLite အင်ဂျင် (`better-sqlite3`) သည် တစ်ခုဖြစ်သည်။** ရွေးချယ်ခွင့်** မှီခိုမှု၊ ထို့ကြောင့် ကမ္ဘာလုံးဆိုင်ရာ ထည့်သွင်းမှုတစ်ခုသည် အရင်းအမြစ်မှ စုစည်းခြင်းကို ဘယ်သောအခါမှ ပိတ်ပင်မည်မဟုတ်ပါ။ ၎င်းသည် သင်၏ platform/Node နှင့် ကိုက်ညီသောအခါတွင် ၎င်းသည် ကြိုတင်တည်ဆောက်ထားသော binary ကို အသုံးပြုကာ၊ သို့မဟုတ်ပါက စစ်မှန်သော JS အင်ဂျင်သို့ ပွင့်လင်းမြင်သာစွာ ပြန်ကျသွားသည် ( Node 22 + တွင်`node:sqlite` ၊ အခြား အစုလိုက်အစည်းလိုက် `sql.js` WASM) — မလိုအပ်ပါ။

အင်စတောလုပ်ပြီးနောက် ကျော်သွားပါ။** ဇာတိသွေးပူ** လုံးလုံး (CI၊ ခေါင်းမဲ့ သို့မဟုတ် အနှေးစက်များ)။ မှတ်ချက်- ၎င်းသည် မူလ SQLite သွေးပူခြင်း အဆင့် (`scripts/postinstall.mjs`) ကိုသာ ကျော်သွားသည် ။ binary-copy/repair ချိတ် (`scripts/build/postinstall.mjs`) သည် ပုံမှန်အတိုင်းလည်ပတ်နေဆဲဖြစ်သည်-

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

အမြန်ဆုံး တပ်ဆင်မှုများအတွက် ပိုနှစ်သက်သည်။** pnpm** (အကြောင်းအရာ-လိပ်စာစတိုးဆိုင် + hard links — အပေါ်ကိုကြည့်ပါ)။ ဒက်ရှ်ဘုတ်မပါသော၊ ဦးခေါင်းမပါသော runtime အတွက် Docker `base` ပရိုဖိုင် (အထက်) သို့မဟုတ် [Termux လမ်းညွှန်ကို](docs/guides/TERMUX_GUIDE.md) အသုံးပြုပါ။ CLI နှင့် ဝဘ်ဒက်ရှ်ဘုတ်ကို ဆိပ်ကမ်းတစ်ခုတည်းတွင် တူညီသောလုပ်ငန်းစဉ်ဖြင့် လုပ်ဆောင်ပေးသောကြောင့် ယနေ့တွင် သီးခြား CLI-သီးသန့်ပက်ကေ့ချ် မရှိပါ။

6. **base = ထို `release/vX.Y.Z` branch** ဖြင့် Pull Request ဖွင့်ပါ
